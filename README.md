# D2P Project Website

**Data-Driven Policy for Pesticide Poisoning Surveillance in South Africa**

This Quarto website showcases the research outputs from the D2P Project, which evaluates policy options for strengthening pesticide poisoning surveillance in South Africa.

## Website Structure

```
D2P_project/
├── _quarto.yml              # Website configuration
├── index.qmd                # Homepage
├── one_pager.qmd            # One-page synopsis for policymakers
├── styles.css               # Custom CSS styling
├── custom.scss              # Custom SCSS theme
├── posts/                   # Blog posts directory
│   ├── surveillance_concept_note.qmd
│   ├── policy_brief.qmd
│   ├── decision_model.qmd
│   └── costing_analysis.qmd
├── analysis_report_v2.qmd   # Full analysis report
└── _site/                   # Generated website (HTML output)
```

### Main Pages

## Building the Website

### Prerequisites

- [Quarto](https://quarto.org/docs/get-started/) (v1.3 or later)
- R (v4.3 or later) with packages:
  - tidyverse
  - gt
  - ggplot2
  - scales

### Render the Website

From the project directory, run:

```bash
quarto render
```

This will generate the website in the `_site/` directory.

### Preview Locally

To preview the website with live reloading:

```bash
quarto preview
```

This will open the website in your default browser at `http://localhost:XXXX`.

### Publish the Website

#### Option 1 (recommended for collaborators): one-command R deploy script

If you don't want to learn git/GitHub, use **`deploy.R`** — it renders, commits, pushes, and publishes in one step.

**From R or RStudio:**

```r
source("deploy.R")
deploy("Short description of what you changed")
```

**From the terminal:**

```bash
Rscript deploy.R "Short description of what you changed"
```

One-time setup (only the first time you ever use git on this machine):

```bash
git config --global user.name  "Your Name"
git config --global user.email "you@example.com"
```

You also need a way for git to authenticate with GitHub. The easiest is to install [GitHub CLI](https://cli.github.com/) and run `gh auth login` once. The script will tell you if anything is missing.

#### Option 2: bash equivalent

```bash
./publish.sh "Short description of what you changed"
```

(Functionally identical to `deploy.R`; use whichever you prefer.)

#### Option 3: raw Quarto commands

```bash
quarto render
quarto publish gh-pages
```

(You then need to commit + push the source yourself.)

## Customization

### Modify Theme Colors

Edit `custom.scss` to change the color scheme:

```scss
$primary: #0d47a1;    // Primary blue
$secondary: #1a237e;  // Secondary dark blue
$success: #388e3c;    // Success green
```

### Update Navigation

Edit `_quarto.yml` to modify the navbar:

```yaml
navbar:
  left:
    - text: "Home"
      href: index.qmd
    - text: "Your New Page"
      href: new_page.qmd
```

### Add New Blog Posts

1. Create a new `.qmd` file in the `posts/` directory
2. Add YAML frontmatter:

```yaml
---
title: "Your Post Title"
author: "D2P Project Team"
date: today
categories: [your, tags]
---
```

3. The post will automatically appear in the website navigation

## Data Files

The website uses the following data files (not tracked in version control):

- `wrangling_v2.r` - Data processing
- `methods_v2.r` - Analysis functions
